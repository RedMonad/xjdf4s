# M1.1 — Критическая функциональная корректность

Статус: `[~]` переоткрыта (P0 по результатам аудита)

Цель: устранить дефекты, ломающие корректность ядра и примеры спецификации.

## Задачи

### M1.1-1. Разделить документные ссылки и BOM-рёбра (P0)
Находка аудита: `Product.references` агрегирует все IDREF всех интентов, а
`Bom.toTreeEval` трактует весь поток как рёбра «родитель → дочерний Product».
В поток попадают `Glue/@GlueRef` (ссылка на `MiscConsumable`, Table 8.29),
`AssemblingIntent/@Container`, ссылки `BindIn`/`StickOn` и др. Валидный продукт
с клеем превращается в ложный `BOM-UNRESOLVED-CHILDREF`.

Норма: §3.3.1.1, Examples 3.4/3.5 задают состав BOM конкретными ссылками на
дочерние продукты (`BindingIntent/@ChildRefs`, `VariableIntent/@ChildRefs`).

Решение:
- Добавить `IntentPayload.productChildRefs: Chain[IdRef]` — только нормативные
  child-product связи.
- `Product.references` оставить полным IDREF-обходом (для §2.2.3).
- `Bom` и `checkPartVersion` перевести на `productChildRefs`.

Критерий: явный список, какие ссылки каждого интента являются composition edges
(по каждой таблице), а не фильтрация по имени. Регрессионный тест: продукт с
`Glue/@GlueRef` на Resource не даёт `BomUnresolvedChildRef`.

### M1.1-2. Стек-безопасный `Bom.totalCopies` (P2)
Находка аудита: unfold и cata используют `Eval`, но `totalCopies` — прямая
рекурсия; умножение amounts — обычный `Long * Long` (переполнение).

Решение: переписать `totalCopies` через `Eval.defer` / explicit work stack;
использовать checked arithmetic (`Math.multiplyExact` или `BigInt`).
Критерий: deep-тест глубины ≥ 10 000 вызывает `totalCopies` без `StackOverflowError`.

### M1.1-3. Уточнить `IntegerRange` (P2)
Переименовать `lo`/`hi` → `clampedFrom`/`clampedTo`; добавить граничные тесты
(пустой список, выход за границы, отрицательные индексы, обратный диапазон).
Семантику не менять.

## Definition of Done M1.1
- BOM-кейсы зелёные; примеры со `@ChildRefs` разворачиваются без ложных циклов.
- `totalCopies` stack-safe и не переполняется.
- Нисходящий `IntegerRange` подтверждён тестом.
