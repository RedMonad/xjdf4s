## Зачем это нужно

К этому моменту в проекте сотни типов и несколько слоёв. Вопросы «а все ли инстансы
`Eq` согласованы с `Hash`?», «а codec действительно изоморфен?», «а не сломал ли я
бинарную совместимость?» должны отвечаться **машиной**, а не ревью. Это этап
индустриализации.

## Дизайн

### 1. Полная деривация инстансов

Этап 01 дал `Eq`/`Show`/`Hash` для малых типов. Здесь: **все** публичные ADT получают
`Eq`/`Show`/`Hash` через kittens (`derives Eq, Show, Hash`), плюс ручные инстансы там,
где деривация неверна (float-поля — `Eq` с допуском; `Map`-поля — порядко-независимое
сравнение, если это семантика). Результат фиксируется тестом:

```scala
test("derived Eq agrees with case class equality") {
  // для выборочных типов: Eq.eqv(a, b) == (a == b) на эталонных парах
}
```

### 2. Законы для инстансов

```scala
class XjdfLawSuite extends munit.DisciplineSuite:
  checkAll("Eq[IntegerRange]",   EqTests[IntegerRange].eq)
  checkAll("Monoid[Extensions]", MonoidTests[Extensions].monoid)
  checkAll("Hash[QualifiedName]", HashTests[QualifiedName].hash)
```

Зависимости: `cats-laws`, `discipline-core`, `discipline-munit`, `scalacheck`
(через `munit-scalacheck`). Генераторы `Arbitrary` пишутся вручную для доменных типов —
это самая трудоёмкая часть; начните со скаляров и малых значений, ресурсы добавляйте
слоями.

### 3. Законы кодеков (round-trip и кросс-кодек)

Property-формулировка законов этапов 04–05:

```scala
property("XML round-trip") {
  forAll(arbitrary[ResourceSet]) { rs =>
    decode(encode(rs)) == Right(rs)   // с Eq-допуском для float
  }
}

property("XML/JSON agree") {
  forAll(arbitrary[Media]) { media =>
    decodeXml(encodeXml(media)) == decodeJson(encodeJson(media))
  }
}
```

Плюс «отрицательные» свойства: мутации валидного XML (битый токен, потерянный атрибут)
должны давать ошибку, а не молчаливый мусор.

### 4. Законы Free-алгебр

Для `DocOp`/`XjmfOp`:

- **монадические законы** Free следуют из cats (проверять не нужно — это закон библиотеки);
- **интерпретаторные законы** — свои и важные: «сборка программы эквивалентна прямому
  конструированию документа» (`run(program, seed) == handBuilt`), «трасса журнала
  воспроизводит порядок шагов», «dry-run валидации не слабее валидации результата».

### 5. Строгий CI и публикация

- **sbt-typelevel** (экосистемный плагин): единый стек для CI, версионирования,
  Sonatype, MiMa:
  - `sbt tlCiHeaderCheck`, `scalafmtCheckAll`, `+test` на JDK 17/21;
  - MiMa (Migration Manager) для бинарной совместимости между релизами — критично,
    потому что модель публичная;
  - версии: sbt-typelevel считает semver из тегов; до 1.0.0 — `0.x` с MiMa на каждом PR.
- **Политика модулей** (финальная): `core`, `model`, `messaging`, `protocol` (домен,
  без тяжёлых зависимостей) + `dsl`, `codec-xml`, `codec-json`, `xjmf`, `http`.
  Домен остаётся зависимым только от cats-core.
- **Документация**: примеры с `mdoc` (компилируемые примеры не протухают);
  генерация сайта — по желанию (sbt-typelevel-site).

## Задачи (пошагово)

1. kittens-деривация `Eq`/`Show`/`Hash` по всем публичным типам; ручные инстансы для
   float- и Map-полей; тест согласованности с `==`.
2. `cats-laws` + discipline + munit-scalacheck; `Arbitrary`-генераторы по слоям
   (скаляры → значения → узлы → документы).
3. Законы инстансов (Eq/Hash/Monoid) — зелёные для всего, что продеривировано.
4. Property round-trip XML/JSON на генераторах + негативные мутационные свойства.
5. Интерпретаторные законы DSL/транспорта (п. 4 дизайна).
6. sbt-typelevel: CI, scalafmt, MiMa, версионирование; первый PR с зелёным CI.
7. mdoc-примеры (submit XJDF, подписка) как часть README; публикация snapshot'ов.

## Definition of Done

- [ ] Все публичные ADT имеют `Eq`/`Show`/`Hash` (derived или ручные) — покрыто законами.
- [ ] Round-trip и кросс-кодековые свойства зелёные на генераторах.
- [ ] Интерпретаторные законы DSL/транспорта зелёные.

- [ ] MiMa включён; политика модулей и версионирования задокументирована.
- [ ] Документация с компилируемыми примерами.

## Риски и альтернативы

- **Генераторы — бутылочное горлышко.** Пишите их рядом с типами и переиспользуйте
  (`Arbitrary[Nmtoken]` → `Arbitrary[Part]` → `Arbitrary[Resource]`); не генерируйте
  «всё сразу».
- **Float-свойства флакают** — фиксируйте допуск и политику NaN/INF в одном месте
  (этапы 01/05), иначе законы будут краснеть случайно.
- **MiMa на ранних 0.x** — можно отложить строгость до 1.0, но лучше включить сразу:
  ломать публичную модель без шума — плохая привычка.
- **Объём деривации ~200 типов** — делайте итерациями по модулям, каждая итерация —
  отдельный PR с законами; не блокируйте релиз этапа 07 ради 100% покрытия.
