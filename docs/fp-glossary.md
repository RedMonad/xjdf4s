# Глоссарий FP-терминов xjdf4s

Минимум понятий, чтобы читать код, тесты и roadmap. Термины идут от простых к сложным; у каждого —
ссылка на главу справочника `reference/cats/docs/`, где тема разобрана глубже.

## Чистая функция и ссылочная прозрачность

Функция чистая, если результат зависит только от аргументов и у неё нет побочных эффектов
(ввода-вывода, мутаций, исключений). Тогда вызов можно заменить его результатом — это **ссылочная
прозрачность**. Весь доменный слой xjdf4s (`core`–`protocol`) чистый; эффекты допускаются только в
рантайм-слое (этап 07 roadmap).

## ADT: сумма и произведение

Алгебраический тип данных — тип, собранный из «и» (произведение: `case class`) и «или»
(сумма: `enum`). В модели: `Resource` — произведение полей; `FileLocation` — сумма взаимоисключающих
вариантов; `enum MediaLayer` — сумма `GlueLayer | MediaLayer`. Сумма гарантирует: невозможно забыть
вариант при pattern matching (`-Werror` + exhaustivity).

## Type class и инстансы

Type class — интерфейс, объявленный **отдельно от типа данных**: `Eq[A]`, `Show[A]`, `Monoid[A]`.
Инстанс — «доказательство», что конкретный тип реализует интерфейс: `given Eq[Nmtoken] = ...`.
Поиск инстанса идёт через implicit scope (companion типа или класса типов) и `using`-параметры —
никакого наследования. См. `typeclasses/eq.md`, `typeclasses/monoid.md`.

```scala
assert(Eq[Nmtoken].eqv(a, b))      // инстанс найден в companion Nmtoken
```

## Законы

Свойства, которым обязан удовлетворять каждый инстанс (ассоциативность `|+|`, `empty |+| a == a`,
`x == y ⇒ hash(x) == hash(y)`). Проверяются тестами; с этапа 08 — property-based (см. ниже) через
`cats-laws`. Точное равенство чисел с плавающей точкой в законах кодеков заменяют сравнением с
допуском, иначе round-trip «флакает» на представлении `80.0f`.

## Semigroup и Monoid

`Semigroup[A]` — ассоциативная операция `combine` (`|+|`). `Monoid[A]` — полугруппа с нейтральным
`empty`. В модели: `Extensions |+| Extensions` склеивает wildcard-атрибуты (right-biased) и foreign-детей.
См. `typeclasses/semigroup.md`, `typeclasses/monoid.md`.

## Functor, Applicative, Monad

Три ступени «вычислений в контексте F[A]»:

- **Functor** — `map`: применить чистую функцию внутри контекста (`F[A] → F[B]`);
- **Applicative** — `mapN`/`product`: скомбинировать несколько независимых `F` без зависимости;
- **Monad** — `flatMap`: следующее вычисление зависит от значения предыдущего (for-comprehension).

Валидация xjdf4s опирается именно на Applicative `Validated`: независимые проверки комбинируются
**без** короткого замыкания, ошибки накапливаются.

## Validated и ValidatedNel

`Validated[E, A]` = `Valid(a)` или `Invalid(e)` — как `Either`, но с **аккумулирующей** семантикой:
`Invalid(e1) *> Invalid(e2) = Invalid(e1 ++ e2)`. `ValidatedNel[E, A]` — сокращение для
`Validated[NonEmptyList[E], A]`: ошибки собираются в непустой список (в cats есть и вариант на
`NonEmptyChain` — `ValidatedNec`; в xjdf4s используется классический `ValidatedNel`). См.
`datatypes/validated.md`, `datatypes/nel.md`, `datatypes/chain.md`.

```scala
document.validateAll              // ValidatedNel[ValidationError, Unit] — все ошибки документа разом
errors.toValidatedNel.toEither    // fail-fast перевод
```

## Ior

`Ior[A, B]` = «или A, или B, **или оба**»: `Ior.both(warnings, value)` выражает «значение получено,
но с предупреждениями». В текущей модели для простоты используется `ValidationOutcome(errors, warnings)`;
`Ior` — тип для кодек-слоя, когда результат и предупреждения идут в одном типе. См. `datatypes/ior.md`.

## Traverse

`traverse`/`traverse_` — пройти по коллекции, применить эффектную функцию к каждому элементу и
собрать результаты «навыворот»: `Vector[A].traverse_(a => ValidatedNel[E, Unit])` даёт одну ошибку-цепочку
на всю коллекцию. Основа `XJDF.validateAll`. См. `typeclasses/traverse.md`.

## Free-монад

`Free[F, A]` — монада, построенная **бесплатно** из любого `Functor`-алгебры F: программа — это дерево
инструкций (данные), а не исполнение. `Free.liftF` поднимает инструкцию в программу, `foldMap` исполняет
программу через интерпретатор. В xjdf4s: `DocDsl[A] = Free[DocOp, A]`. См. `datatypes/freemonad.md`,
а для теории — `reference/category-theory/Part 3 – free-forgetful-adjunctions.md`.

Интуиция: программа на Free — **список покупок**; кассир, менеджер и курьер — разные интерпретаторы
одного списка.

## Интерпретатор и натуральное преобразование (FunctionK)

Интерпретатор Free-программы — **натуральное преобразование** `F ~> G` (синоним `FunctionK[F, G]`):
преобразование, которое переводит `F[A]` в `G[A]` **для любого A**, не заглядывая в значение. Именно
поэтому интерпретатор нельзя «подогнать» под конкретный тип. См. `datatypes/functionk.md`.

## State, Writer, Reader/Kleisli

Три классических «эффекта-состояния» как чистые типы:

- `State[S, A]` = функция `S => (S, A)`: сборка документа — накопление состояния;
- `Writer[L, A]` = `(L, A)` с аккумуляцией журнала: трасса программы;
- `Reader`/`Kleisli[F, Env, A]` = функция из окружения с эффектом F: декодеры кодеков (этап 04).

См. `datatypes/state.md`, `datatypes/writer.md`, `datatypes/kleisli.md`.

## Tagless final

Альтернатива Free: программа пишется полиморфно по эффекту `F[_]` (`Doc[F]`), инстансы type class'ов
даются на месте использования. Плюс — нативный синтаксис; минус — интерпретатор выбирается **при
компиляции**, одну программу нельзя исполнить несколькими способами. В xjdf4s: Free — для публичных
программ-сценариев, tagless — для внутренних capability рантайма (этап 06 roadmap).

## Эффекты и IO

`IO[A]` (cats-effect) — описание эффектного вычисления как значения; исполняется только рантаймом.
Появляется в xjdf4s на этапе 07 (http4s/fs2) и **только** в новых интерпретаторах — домен и алгебры
остаются чистыми.

## Round-trip-закон

`decode(encode(a)) == a` — кодек без потерь. В xjdf4s этот закон уже работает для XML-кодека
(`codec-xml`: round-trip на нормативных фикстурах Example 7.5/8.5/7.8 и покрытых узлах); для JSON он
появится на этапе 05 вместе с кросс-законом: XML- и JSON-декод одного значения дают равные ADT.

## Property-based testing

Вместо фиксированных примеров — свойства над случайно сгенерированными значениями
(«для любого `ResourceSet` декод(энкод(x)) == x»). Генераторы (`Arbitrary`) пишутся послойно;
инструменты — scalacheck + discipline + `cats-laws` (этап 08). См. `typeclasses/lawtesting.md`.

## Деривация инстансов (kittens)

Механическое порождение инстансов `Eq`/`Show`/`Hash` для `case class` через `derives` (библиотека
kittens). В этапах 01–03 инстансы написаны вручную (их немного); массовая деривация — этап 08,
где окупается на сотнях типов.
